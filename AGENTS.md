# Правила работы с Waiter

Waiter — приложение для изучения ресторанного меню и обучения персонала. Источник продуктовых требований — документы внутри репозитория, прежде всего [docs/product/mvp.md](docs/product/mvp.md). Текущее устройство и команды — в [README.md](README.md) и [docs/architecture/current.md](docs/architecture/current.md). Прямые указания пользователя имеют приоритет. Различай согласованные требования, реализацию и планы; не превращай нерешённые вопросы в требования.

Перед изменениями проверяй актуальные код, конфигурацию и связанные документы. Obsidian-vault `C:\Users\ruzin\OneDrive\Obsidian\My_notes\Codex-waiter\` — необязательный исторический источник. Если он доступен и полезен, начинай с `00-MOC.md` и читай заметки по теме; его недоступность не блокирует работу. Новые архитектурные решения сначала предлагай на согласование. Не требуй обновления `decisions.md`, пока файл не создан.

Отвечай по-русски, объясняй архитектурные решения и прямо указывай неизвестное. Меняй только относящиеся к задаче файлы; не удаляй файлы без подтверждения, не изменяй `.env` и секреты. Не запрашивай лишних подтверждений для обычной работы в разрешённых границах.

Разрешены безопасные операции анализа: `git status`, `git diff`, чтение истории Git, проверки TypeScript, ESLint, тесты и сборка. При необходимости воспроизвести существующий проект разрешён `npm ci`; добавление или обновление зависимостей требует отдельного согласования. Commit, push, merge, смена ветки, изменения базы данных и production выполняются только по явному заданию. Перед любой операцией с данными проверяй фактическую строку подключения и целевое окружение, не раскрывая секреты. Не запускай seed, db push или reset без явного разрешения.

В отчёте укажи изменённые файлы и смысл изменений, выполненные проверки и их результаты, обнаруженные расхождения и существенные ограничения. Не выдавай планы за готовую реализацию.
