# Waiter

Waiter — приложение для изучения ресторанного меню и обучения персонала. Согласованный состав MVP приведён в [docs/product/mvp.md](docs/product/mvp.md). Проект развивается из клона Dodo Pizza и пока содержит легаси.

## Текущее состояние кода

Главная страница загружает опубликованные блюда из PostgreSQL через Prisma и показывает каталог по категориям с фильтрами по ингредиентам и аллергенам. Поиск ищет опубликованные блюда по названию. При выборе блюда открывается модальное окно в состоянии клиента; постоянная ссылка на блюдо не реализована. Админ-панели в текущем дереве маршрутов нет. Требования MVP шире текущей реализации.

Старый код корзины, оплаты, авторизации и Stories остаётся в репозитории. Middleware закрывает старые API и маршруты оформления заказа и профиля; регистрация и оформление заказа в серверных действиях отключены. Наличие кода не означает доступность этих функций в текущем интерфейсе.

## Технологии

Next.js 15 (App Router, Turbopack), React 19 и TypeScript; PostgreSQL и Prisma 6; Tailwind CSS 4, Radix UI и Lucide; Zustand; React Hook Form и Zod. В легаси также присутствуют NextAuth, интеграции оплаты и электронной почты.

## Локальный запуск

Нужны Node.js, npm, установленные зависимости и доступная PostgreSQL с подходящей схемой и данными. Версия Node в проекте не закреплена. Prisma читает строку подключения из переменной `POSTGRES_URL` в `.env`; образца `.env.example` в репозитории сейчас нет. Не публикуйте секреты. По прежним сведениям dev и prod используют общую базу: проверьте подключение до работы с данными.

```bash
npm install
npx prisma generate
npm run dev
```

Откройте http://localhost:3000. `npm run dev` запускает Next.js с Turbopack. Генерация Prisma Client не изменяет схему базы. Для установки зависимостей в рабочей среде соблюдайте правила проекта и предварительно согласуйте её.

## Проверки и другие команды

```bash
npm run lint
npx tsc --noEmit --incremental false
node --test tests/*.test.cjs
npm run build
npm start
```

`lint` запускает ESLint; `tsc` проверяет типы отдельно; тесты запускаются встроенным тестовым модулем Node.js. `build` выполняет `next build --turbopack`, а `start` запускает собранное приложение. Сборке может понадобиться доступ к базе: главная страница получает данные из неё. Успех сборки сам по себе не подтверждает выполнение продуктовых требований.

В `package.json` также есть команды `prisma:studio`, `prisma:push` и `prisma:seed`. Push и seed изменяют данные или схему базы и не должны запускаться без явного разрешения и проверки подключения; reset также запрещён без разрешения.

## Запланированные изменения

Дальнейшая работа должна привести реализацию к требованиям MVP: в частности, обеспечить необязательные поля и категории, вложенные ингредиенты и поиск по ним, прямые ссылки на модальные карточки и администрирование. Это планируемые изменения, а не описание уже работающих функций.
